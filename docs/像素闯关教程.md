# 用一关像素冒险讲清Skill

## 这套画面能做什么

适合把「给AI提任务、整理方法、复用方法、检查结果」这类抽象流程，转成看得见的教学剧情。也可以改成产品使用步骤、课程导览、学习任务或工具入门。

这不是仅把普通卡片换成像素边框。角色沿地图前进，经过具名NPC，接到问号任务，跑跳、过桥、开宝箱、获得技能书，再进入下一项任务。NPC承担讲解，弹框有展开、逐字显示、姓名牌、头像、尾巴和继续提示。

## 文件怎么对应画面

- `assets/quest.html`：预览入口，加载像素字体和代码。
- `assets/quest-original-expanded.js`：原版绘制系统与约一分钟扩展剧情，是实际运行的完整文件。
- `assets/quest-extension.js`：同一扩展部分的单独维护副本，便于读剧情。仅改这个副本不会自动改变运行画面。
- `assets/assets/cues.json`：原十秒开场动作事件。
- `references/story.md`：任务结构与修改顺序。

约0–7秒为跑跳、宝箱和技能书钩子；后续依次接任务、保存方法、复用技能书、参观像素制作工坊、继续闯关；结尾由NPC给出A/B选择。片长取自页面window.film.duration，不写死成任何新稿都适用的长度。

## 换主题的实际顺序

1. 写清观众看完要懂的一件事，先给出能演示的结果。
2. 写口播，把内容拆成「接任务→试做→获得方法→换任务复用→检查→互动」。
3. 得到最终配音后，逐句转写，记录真正的开始和结束时间。
4. 修改 `STORY_PATH` 的时间和世界坐标；角色停在对话NPC附近，移动时才跑步。
5. 修改 `NPCS`、`TALKS`、`STORY_JUMPS` 和奖励时刻。TALKS中的NPC编号必须对应NPCS。
6. 开头动作、字幕、NPC弹框都按同一条新声音对齐。不要把所有时间点简单等比例拉伸就宣布对齐。
7. 逐帧检查脚底接地、落地点、对话框遮挡、任务问号光效，再导出带声音的完整版本。

同步扩展副本时，运行 `python tools/sync_pixel_story.py`；它只替换完整文件的扩展部分，先自动备份，不改原绘制系统。也可让Codex直接修改实际运行的完整文件并同步维护副本。

## 像素质量要求

画面以320×180的逻辑像素绘制、有限色板和精灵动作构成，再用整数倍显示到1920×1080。保持硬边与最近邻思路，避免水彩渐变笔刷、任意粗线门、大块现代卡片或系统字体。问号任务与奖励光效应属于同一套像素语言。

原示例不是一个已经支持键盘、鼠标和真实分支的可玩游戏。影片中的A/B是互动提问；要做游戏还需另做输入、碰撞、状态、分支与存档。

本片制作中用到Pixel Art Sprites这类像素设计知识；这次分享的是完整的pixel-skill-quest封装、实际绘制代码和操作教程，不将一份设计知识说明冒称为渲染模型。
